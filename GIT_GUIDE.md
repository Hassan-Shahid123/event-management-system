# Quick Git Commands Reference

## Initial Push (What You Need Now)

```bash
# 1. Commit your changes
git commit -m "Refactor: Simplify project structure with SQLite database"

# 2. Push to GitHub
git push origin dev
```

## What Others Need to Do After Pulling

When someone else clones or pulls your project:

```bash
# 1. Clone the repo (first time only)
git clone https://github.com/Hassan-Shahid123/event-management-system.git
cd event-management-system

# 2. Switch to dev branch
git checkout dev

# 3. Install dependencies (THIS IS THE KEY STEP!)
npm install

# 4. Build the project
npm run build

# 5. Test it works
node dist/test.js
```

## What Gets Installed When Others Run `npm install`

The `package.json` file tells npm what to install. For this project:

### Production Dependencies:
- **sql.js** (^1.10.3) - SQLite database library

### Development Dependencies:
- **typescript** (^5.3.0) - TypeScript compiler
- **@types/sql.js** - TypeScript type definitions for sql.js
- **@types/node** (^20.0.0) - TypeScript types for Node.js
- **jest** (^29.7.0) - Testing framework
- **ts-jest** (^29.1.0) - Jest TypeScript integration
- **@types/jest** (^29.5.0) - TypeScript types for Jest

**Total Download Size**: ~50-70 MB (will download to their `node_modules/` folder)

## Why `sql.js` is Better for Collaboration

✅ **No native compilation** - Works on Windows, Mac, and Linux without extra tools
✅ **No Python required**
✅ **No Visual Studio Build Tools required**
✅ **Simple npm install** - Just works!

This is why we switched from `better-sqlite3` to `sql.js`.

## Important: What's NOT Pushed to GitHub

Thanks to `.gitignore`, these folders/files won't be pushed:

- ❌ `node_modules/` (70+ MB, regenerated by npm install)
- ❌ `dist/` (build output, regenerated by npm run build)
- ❌ `*.db` (database files with local data)
- ❌ `package-lock.json` (can cause merge conflicts)

## Common Workflow

### You (making changes):
```bash
git add .
git commit -m "Add new feature"
git push origin dev
```

### Others (getting your changes):
```bash
git pull origin dev
npm install          # Only if package.json changed
npm run build        # Rebuild after pulling new code
```

## Branch Strategy

- **main** - Stable, production-ready code
- **dev** - Development branch (you're currently here)
- **feature/*** - Feature branches for new work

## Quick Tips

1. **Always check what you're committing**:
   ```bash
   git status
   git diff
   ```

2. **Don't commit sensitive data**:
   - Passwords
   - API keys
   - Database files with real data
   - `.env` files

3. **Write clear commit messages**:
   - ✅ "Add user authentication with JWT"
   - ✅ "Fix: Resolve database connection timeout"
   - ❌ "Update stuff"
   - ❌ "asdf"

4. **Pull before push**:
   ```bash
   git pull origin dev
   git push origin dev
   ```
