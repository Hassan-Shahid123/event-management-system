# Getting Started - For Team Members

This guide will help you set up the project after cloning from GitHub and start contributing.

## Prerequisites

Before you start, make sure you have these installed:

1. **Node.js** (version 18 or higher)
   - Download from: https://nodejs.org/
   - Check your version: `node --version`

2. **npm** (comes with Node.js)
   - Check your version: `npm --version`

3. **Git**
   - Download from: https://git-scm.com/
   - Check your version: `git --version`

## Initial Setup

### 1. Clone the Repository

```bash
git clone https://github.com/Hassan-Shahid123/event-management-system.git
cd event-management-system
```

### 2. Switch to Development Branch

```bash
git checkout dev
```

**Note**: We use the `dev` branch for active development. The `main` branch is for stable releases.

### 3. Install Dependencies

```bash
npm install
```

This will install:
- `sql.js` - SQLite database (pure JavaScript, no native compilation needed)
- `uuid` - For generating unique IDs
- `typescript` - TypeScript compiler
- `jest` - Testing framework
- Other development dependencies

**Important**: Unlike `better-sqlite3`, `sql.js` doesn't require Visual Studio Build Tools or Python, so installation works on any system without additional setup!

### 4. Build the Project

```bash
npm run build
```

This compiles TypeScript files from `src/` to JavaScript in `dist/`.

### 5. Run the Test

```bash
node dist/test.js
```

You should see:
```
_/ All tests passed!
```

## Git Workflow

### Daily Development Workflow

1. **Always pull latest changes before starting work**:
```bash
git checkout dev
git pull origin dev
```

2. **Create a feature branch for your work**:
```bash
git checkout -b feature/your-feature-name
# Examples:
# git checkout -b feature/add-authentication
# git checkout -b feature/event-search
# git checkout -b fix/registration-bug
```

3. **Make your changes and test**:
```bash
npm run build
npm test  # When tests are available
node dist/test.js
```

4. **Stage and commit your changes**:
```bash
git add .
git status  # Review what you're committing
git commit -m "Clear description of what you changed"
```

**Good commit messages**:
- _/ `Add user authentication with JWT`
- _/ `Fix: Resolve waitlist promotion bug`
- _/ `Refactor: Simplify event repository queries`
- X `Update stuff`
- X `asdf`

5. **Push your branch to GitHub**:
```bash
git push origin feature/your-feature-name
```

6. **Create a Pull Request**:
   - Go to GitHub repository
   - Click "Pull Requests" → "New Pull Request"
   - Base: `dev` ← Compare: `feature/your-feature-name`
   - Add description of changes
   - Request review from team members

### Keeping Your Branch Updated

If the `dev` branch has new changes while you're working:

```bash
git checkout dev
git pull origin dev
git checkout feature/your-feature-name
git merge dev
# Resolve any conflicts if they occur
```

### What to Commit

**DO commit** _/:
- `src/` - All source code
- `package.json` - Dependencies list
- `tsconfig.json`, `jest.config.js` - Configuration files
- `.gitignore` - Git ignore rules
- Documentation files (*.md)

**DON'T commit** X:
- `node_modules/` - Dependencies (~70MB, regenerated by `npm install`)
- `dist/` - Build output (regenerated by `npm run build`)
- `*.db` - Database files (contains local data)
- `package-lock.json` - Already in .gitignore to avoid conflicts
- IDE-specific files (`.vscode/`, `.idea/`)

### Common Git Commands

```bash
# Check current branch and status
git status
git branch

# See what changed
git diff

# Discard local changes to a file
git checkout -- filename

# Undo last commit (keep changes)
git reset --soft HEAD~1

# Switch branches
git checkout branch-name

# Delete local branch
git branch -d feature/branch-name

# See commit history
git log --oneline
```

## Troubleshooting

### Issue: `npm install` fails

**Solution 1**: Clear npm cache and retry
```bash
npm cache clean --force
npm install
```

**Solution 2**: Delete `node_modules` and retry
```bash
# Windows PowerShell:
Remove-Item -Path node_modules -Recurse -Force
npm install

# Mac/Linux:
rm -rf node_modules
npm install
```

### Issue: Build fails with TypeScript errors

**Solution**: Ensure you have latest dependencies and rebuild
```bash
npm install
npm run build
```

### Issue: Git merge conflicts

**Solution**: 
1. Open conflicted files (Git marks conflicts with `<<<<<<<`, `=======`, `>>>>>>>`)
2. Manually edit to keep the correct code
3. Remove conflict markers
4. Stage and commit:
```bash
git add .
git commit -m "Resolve merge conflicts"
```

### Issue: Accidentally committed to wrong branch

**Solution**: Move commits to correct branch
```bash
# Create a new branch with current commits
git branch feature/correct-branch

# Reset current branch to before your commits
git reset --hard origin/dev

# Switch to new branch
git checkout feature/correct-branch
```

## Contributing Guidelines

### Before Submitting a Pull Request

1. _/ Code builds without errors: `npm run build`
2. _/ All tests pass: `npm test` (when available)
3. __/ Code is formatted and readable
4. _/ No console.log() statements left in code
5. _/ Comments added for complex logic
6. _/ Commit messages are clear and descriptive

### Code Style

- Use TypeScript types for all functions
- Follow existing naming conventions (camelCase for variables/functions)
- Add JSDoc comments for public functions
- Keep functions small and focused
- Use async/await for asynchronous code

### Repository Access

Repository functions handle all database operations. When building services:

```typescript
// _/ Good - Use repository functions
import { createUser, getUserByEmail } from './repositories';
const user = await getUserByEmail('hassan@example.com');

// X Bad - Don't write raw SQL in services
const db = await getDatabase();
db.exec('SELECT * FROM users WHERE email = ?', [email]);
```
